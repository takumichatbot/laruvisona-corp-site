# 予約確定通知の再送

予約確定、日時変更、キャンセル、返金完了は、予約と同じトランザクションで `hp_booking_events` に保存される。メール障害で即時送信できなかったイベントを、5分ごとの内部実行が再送する。

- DBの期限順ロックと10分の取得票で同時実行を分離する。
- 店舗・顧客それぞれの送信済みフラグを保ち、成功済みの宛先には再送しない。
- Resendへ渡すidempotency keyは既存のイベントID・宛先種別から変えない。
- 最大5回、23時間以内だけ再試行する。長期間後に古い予約通知を突然送らない。
- 取得処理が消えた場合は10分後に回収する。
- DBの更新0件を成功にせず、キューの取得票が一致する実行だけが結果を確定する。

反映は `hp_scheduling.sql` の後に `hp_scheduling_notifications.sql`、続いてコードの順。既存イベントは削除しない。必要な既存設定は `ADMIN_SECRET` と `RESEND_API_KEY`。
