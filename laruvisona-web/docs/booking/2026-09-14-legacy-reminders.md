# 旧予約リマインダーの安全な終了

旧固定枠フォームの確定予約は、本格予約へ切り替えたあとも予約日までは残る。このため旧経路を削除せず、送信処理だけを本格予約と同じ15分周期の耐久処理へ移した。

`hp_reservations_reminded.sql` は、未送信・取得中・失敗・送信済みをDBに保存する。取得は `FOR UPDATE SKIP LOCKED` と10分のリースを使い、複数インスタンスが同じ予約を同時に受け取らない。送信は予約IDをResendの冪等キーに使い、事業者の成功応答と取得票つきのDB更新が両方通った場合だけ `reminded=true` にする。失敗は最大5回、間隔を延ばして再試行する。

メールはHTMLとして組み立てず平文で送る。店舗名の改行と制御文字は件名から除く。利用者ロールが内部の送信状態を直接変更した場合はDBトリガで拒否する。

本番では `hp_reservations.sql`、`hp_reservations_reminded.sql` の順に適用する。旧確定予約が0件になるまで互換ワーカーを残し、0件になったことを確認してから別の変更単位で削除する。
