# 受託の見せ方を組み直す（2026-09-16）

ブランチ: `company-customers-2026-09-16`（続き）

## なぜ

受託の受注を増やしたい。問い合わせは月0〜2件。
料金表自体は揃っていたが、次の3点が受注を取りこぼす形になっていた。

1. 保守が「任意」だった。半分の人は外す。一人でやる受託で、
   毎月入る収入と、次の相談が向こうから来る経路を、自分から手放していた。
2. 大きい仕事しか並んでいなかった。「フォームが壊れた」という人の行き先が、
   会社トップには一つも無かった。
3. 業務の仕組みづくりとサービス開発が「AI組み込み・システム開発」1枠に
   まとまっていて、日本エンドレスで実際にやっている仕事と、FLASTALで
   やっている仕事が、どちらも見えなかった。

## 変えたこと

### `/services` の料金表（5枠 → 6枠）

| | 変更 |
| --- | --- |
| 01 AIシステム 安全点検 | 据え置き。主役のまま（唯一、競合が薄い） |
| 02 サイト・システムの修理 | 「小さな困りごとでも」「他社が作ったものでも」を明記 |
| 03 ホームページ制作 → **制作・改修** | 作り直し・一部改修も受けることを明記 |
| 04 AI組み込み・システム開発 → **業務の仕組みづくり** | 見積・受注・案件・請求・日報。日本エンドレスで実際にやっている仕事の形に書き直した |
| 05 **Webサービスの開発**（新設 ¥800,000〜） | 決済を含むサービスを企画から運用まで。FLASTALの実績と地続き |
| 06 保守・運用 | **「任意」をやめ、標準でお付けする**。外したい人だけ外す |

04・05には「まずは1画面・2週間から」を添えた。
一人でやる受託で要件定義に溶けるのを避けるためと、速さが武器になるため。

### 会社トップに「04 修理・改修・安全点検」を追加

新しくつくる話が3つ並ぶだけだったので、今あるものを直す枠を同じ並びに置いた。
セクションの一言も「デザインも、その奥の仕組みも。」から
「新しくつくることも、今あるものを直すことも。」に変えた。

### 「こんなときに」を10項目へ

仕組み化、新サービス、決済導入、前の業者と連絡が取れない、を追加した。
