# 書いてあるのに誰も辿り着けない、を全部つぶした（集客）

2026-09-17

## 比較ページ4本が、存在しないのと同じだった

`/laruHP/vs/{jimdo,wix,canva,studio}` は既に書かれていたのに、

- `robots: { index: false, follow: false }`（索引されない）
- `LARUHP_PUBLIC_PATHS` に無く、laruhp.com からは **404**
- sitemap にも無く、外部からの入口はゼロ
- 内部リンクは vs ページ同士の1本だけ

「ホームページ作成 比較」「◯◯ 料金」は、買う直前の検索語です。そこを丸ごと捨てていました。

### ただし、公開する前に中身を書き直した

元の内容は、他社について「AI機能が弱い」「SEO機能なし」「日本語サポート弱い」「デザインが古め」を
**表の×として断定**し、他社の価格も書いていました。出典も調査日も無く、相手の製品は更新されます。
比較広告は、客観的で確かめられる事実にもとづく必要があります。このまま索引させるのは危険でした。

書き方を変えました。

- **他社の機能の有無や金額を、こちらから断定しない**
- 代わりに「**比べるときに何を見るか**」を8つ並べ、その項目について**LARU HPがどうか**だけを書く
  （料金の総額と拘束期間／作りはじめ／公開後の更新／予約と問い合わせ／SEOの自動設定／
  やめるときの持ち出し／独自ドメインの名義／日本語で聞けるか）
- 相手の最新は、**相手の公式料金ページへのリンク**で確かめてもらう
- 「◯◯のほうが向いている場合」を正直に書く

テストで、断定表現が戻ってきたら落ちるようにしました。

## 記事11本と業種15本のあいだに、リンクが1本も無かった

「工務店 ホームページ 見積り」で記事に着いた人が、工務店の業種ページへ行けませんでした。
26ページが横並びで、どれも単発で終わっていました。

- 記事に `relatedIndustries` を持たせ、記事末尾から業種ページへ
- 業種ページには「先に読んでおくと迷わないもの」として記事3本へ
- どの業種からも最低1本の記事へ行けることをテストで固定

## 読み終えた人の行き先が「申し込む」しか無かった

記事・業種・比較ページのCTAが全部「制作スタジオを開く」だけでした。
まだ決めていない人の行き先が無く、相談の入口はフッターまで下りないと出てきませんでした。
**「試す」と「相談する」の2択**に統一しました。

## OG画像が、全ページ同じ1枚だった

`/api/og` で動的に作る仕組みは実装済みなのに、自社ページでは使っていませんでした。
記事11本・業種15本・比較4本をSNSに貼ると、**全部まったく同じ絵**になっていました。
`laruhpOgImage()` を足し、ページごとに違う絵にしました。

## そのほか

- **パンくずの構造化データ**が laruhp.com 側に1つも無かった（記事・業種・比較・困りごとに追加）
- **sitemapに lastmod が無かった**ので、記事を直しても再クロールの合図が出なかった
- **robots.txt が2重定義**（`public/robots.txt` と `app/robots.ts`）。実ファイルが優先されるため、
  あとから足した遮断が効いていなかった → 実ファイルを削除して1本化
- `/works/[slug]` に canonical が無かった（受託を探している人がいちばん見る3ページ）
- `/blog` は記事本体を外部が描くため**本文が1文字も無い**のに、sitemap で「毎週更新」と宣言していた
  → sitemap から外した（サーバー側で記事を取れるようにしたら戻す）
- `/blog` と `/brand` のナビが、存在しないアンカー（`/#works`・`/#contact`）を指していた
- 困りごと12本の「ほかの困りごと」が**全ページで同じ3本**だった（配列の先頭順）。
  後半8本にリンクが集まらず行き止まりになっていた → 自分の位置から順に回す
- **会社サイトに共通フッターが無かった**。困りごとを読んだ人が /works にも /contact にも
  行けなかった → `CompanyFooter` を services / trouble / local / works に適用
- **問い合わせの受け口が iframe フォーム1種類だけ**だった。外部サービスが止まる・
  広告ブロッカーが切ると、受注口が無言で消える → メールの宛先を併記
- LARU HP トップと /services に **FAQPage 構造化データ**（/services にはFAQ自体が無かった）
- LP と料金ページから比較ページへの入口を追加

## テスト

`tests/reachability.test.ts`（10件）。「書いたのに辿り着けない」を機械で見る。

- 比較ページが公開パス・sitemap・索引の3つすべてに入っているか
- 比較ページに他社の欠点の断定が戻っていないか
- 記事↔業種が双方向につながっているか／どの業種からも記事へ行けるか
- 読み物の出口に相談への導線があるか
- 困りごとが後半だけ行き止まりになっていないか
- 会社サイトの下層ページに共通フッターがあるか
- 問い合わせの受け口が1つになっていないか
- 本文の無いページを sitemap に載せていないか
- 画面のFAQと構造化データが同じ配列から作られているか
