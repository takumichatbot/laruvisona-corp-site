# 契約から公開までの、詰まるところを一通り直す（2026-09-16）

## 1. 試用中（trialing）の人は、作れるのに公開できなかった

「使ってよい契約状態か」の判定が、場所ごとに書かれていた。

```
app/api/sites/route.ts        active または trialing  … 作れる
app/api/ai/blog-generate      active または trialing  … 使える
app/api/sites/[id]/publish    active だけ             … 公開できない
```

作らせておいて最後で止めるのが一番悪い。しかも画面には
「サブスクリプションが必要です」と出るので、払ったのに払えていないように見える。

`lib/subscription-access.ts` に定義を1つ置き、4か所をそこへ寄せた。
`past_due`（支払い遅延）は入れていない。止めるのが正しいため。

検査で、場所ごとに書き直していないことも見ている。

## 2. 決済のあと、作りかけのサイトへ戻らなかった

「公開」を押す → 料金画面 → 支払う → **ダッシュボードへ放り出される**。
何を押せば公開できるのか分からないまま終わる。

制作画面（`/laruHP/builder?siteId=...&payment=success`）へ戻すようにした。

戻った時点では、まだ未契約に見えることがある。Stripeは支払い直後に
返してくるが、契約状態を書くのは webhook だからである。そのまま
「公開」を押すとまた料金画面が出る。2秒おきに20秒まで様子を見て、
反映されたら「「公開」を押すと公開できます」と伝える。

## 3. 公開しても、手元に何も残らなかった

公開ボタンを押すと画面にURLが出るだけ。タブを閉じたら、自分のサイトが
どこにあるのか分からなくなる。人に見せるにも、あとで自分で開くにも、
残るものが要る。

はじめての公開だけ、本人へURLを送るようにした
（`lib/site-published-email.ts`）。

- 独自ドメインがあればそちら、無ければ `/hp/<slug>`（`canonicalBase`）
- 何度公開し直しても1通だけ（`idempotencyKey`）
- 送信に失敗しても、公開は成功のまま

## 4. 毎月「契約終了まであと◯日です」と嘘をついていた

ダッシュボードの通知が `contract_ends_at` を見ていた。あれは
「いまの請求期間の終わり」で、支払うたびに翌月へ動く。つまり
**自動更新される契約の人が、毎月かならず更新日の2週間前から
「もうすぐ終わる」と言われていた。**

本当に終わるのは解約済みのときだけなので、そのときだけ出すようにし、
文面も「ご利用できるのはあと◯日です／解約済みのため、この日を過ぎると
公開サイトが止まります」に変えた。

## 5. 計測の署名鍵ひとつで、顧客の公開サイトが全部落ちる状態だった

`app/hp/[slug]/page.tsx` が `signAnalyticsSite(slug)` をそのまま呼んでいた。
この関数は鍵が32文字未満だと `analytics_unavailable` を投げる。
投げると、**顧客の公開サイトが丸ごと500になる。**

止めるべきなのはアクセス計測だけで、顧客のサイトではない。
鍵が使えないときは計測を諦めて本文を出すようにした。

（本番では `ANALYTICS_SIGNING_SECRET` 未設定 →
`SUPABASE_SERVICE_ROLE_KEY` に落ちるので現状は無事。ただし短い値を
設定した瞬間に全顧客サイトが落ちる作りだった。）

## 6. プラン機能表と実物が食い違っていた

`PLAN_FEATURES` は `hp` と `lite` に `analytics` を載せていない。
しかし `hasFeature` を呼ぶ側はどこにも無く、アクセス解析のAPIにも
プラン判定が無いので、**実際には全プランで見られる。**

このまま放っておくと、あとで「hpは解析なし」と読んで作った処理が、
いま見られている利用者から機能を取り上げる。実物に合わせて両方に足し、
有料の線引きにするなら何から直すかを注記した。

## 7. 通し検査が、いまの案内ページに追いついていなかった

`tests/browser/first-run-check.mjs` が main に対して落ちていた。

案内ページの試作は `[role="radio"]` の見せ方選択＋
`この見せ方で作りはじめる` というリンクではなくなっていて、いまは
`CreationLab`（`aria-pressed` のボタン）が選んだ内容を sessionStorage に
置き、`/laruHP/studio?creation=<id>` へ渡して**いきなり編集から始まる**。

2つの入口を両方見るように書き直した。

- 案内の試作 → そのまま制作へ（引き継ぎの表示まで確認）。
  下書きが localStorage に残るので、別の文脈で行い、通し確認に影響させない
- 案内を通らない入口（`?mood=warm`）→ 質問 → 見せ方 → 編集 → 保存 →
  公開 → 直して再公開

### 偽Supabaseに `laruhp_create_site` を足した

サイトの新規作成は RPC を通る（`supabase/hp_sites.sql`）。偽Supabaseに
それが無かったため、**「はじめての人が1件作る」経路を一度も通せていなかった。**
本物のSQLと同じ判断（入力の形、所有数の上限、`site_limit` の返し方）を
偽物側にも書いた。

これで、2026-09-16 に直した「v2ドキュメントが必ず400で落ちる」不具合も、
実ブラウザの通し確認で押さえられるようになった。
