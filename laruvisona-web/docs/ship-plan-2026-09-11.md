## 3. 出す順（案）

前提として、**コードのデプロイと、顧客HTMLの作り直しは別の操作**になっている
（`REPUBLISH_ON_BOOT` を立てなければ、デプロイしても顧客サイトは1行も書かれない）。

### 案1: 一度に出して、作り直しだけ段階的にやる（おすすめ）

0. **出す前に、4章を上から読むだけ実行する**（2つのSHA・保存済みHTMLの版の分布・
   `site_domains` の適用状態・設定の有無）。ここで本番へ書く操作は1つも無い
1. 全コミットをまとめて `main` へ入れて push → デプロイ
   - `REPUBLISH_ON_BOOT` は設定しない
   - `DOMAIN_PROBE_SECRET` は、独自ドメインを使うなら先に設定する
2. **Render の Deploys で、新しいSHAが Live になったことを確かめる**
3. 自社の2ページと制作画面を確かめる（顧客サイトの保存済みHTMLはまだ触れていない）
4. 新版の `dryRun` を1回投げ、`dryRun: true` が返ることを確かめる（4-5）
5. `site_domains.sql` を適用する（runbook のとおり）
6. 顧客サイトの作り直しを、1件 → 5件 → 25件 → 全件
   （`docs/rebuild-migration-2026-09-11.md` の段階3。応答は毎回ファイルに保存する）

**利点**: ブランチを分けて持ち続けなくてよい。作り直しを止めれば、顧客サイトの
見え方は保存済みのままにできる。
**注意**: コードは50コミットぶん一気に変わる。自社ページ・管理画面・制作画面は
その場で新しくなる。

### 案2: 独自ドメインだけ後にする

`main` から独自ドメインの12コミットを外したブランチを作って先に出し、
`site_domains.sql` の適用と一緒に後から出す。

**利点**: SQLの適用とコードの反映を完全に揃えられる。
**注意**: 12コミットは他の変更と重なる部分（`proxy.ts`・`lib/public-site-url.ts`）が

### 4-1. 2つのSHAを、分けて書き留める

```bash
# (a) GitHub main の先端
git ls-remote origin refs/heads/main
```

```
(b) Render が動かしているSHA
    Render の管理画面 → 対象サービス → Deploys
    「Live」になっているデプロイのコミットを控える。
    （Render の実行環境には RENDER_GIT_COMMIT が入るが、
      それを外から読める口はいま無い。画面で確認する）
```

(a) と (b) が違う場合、**本番で動いているコードは (b)** である。
このあとの判断は (b) を基準にする。

### 4-2. 保存済みHTMLの版を数える（読み取りだけ）

Supabase の SQL Editor で実行する。**書き込みは1行も無い。**

```sql
-- 公開中のサイトが、いまどの版のHTMLで保存されているか
select
  coalesce(substring(published_html from '<!--lhpv:([0-9]+)-->'), '（版の印なし）') as version,
  count(*) as sites
from public.sites
where published is true
group by 1
order by 1;
```

「版の印なし」は、印を埋め込む前のコードで公開された行。作り直しの対象になる。

```sql
-- 作り直しの対象になる件数だけを先に知りたいとき（いまの版に揃っていない行）
-- ※ lib/html-export.ts の EXPORT_VERSION と同じ数字にすること
select count(*)
from public.sites
where published is true
  and (published_html is null or published_html not like '%<!--lhpv:11-->%');
```

**`27` `28` は「積み残し」。** 現行の `site_domains.sql` は

**当てただけでは false になる。** 検査の誤りではない。

revoke truncate, references, trigger on public.site_domains, public.domain_release_queue

- `create or replace function` は**既存の定義を置き換える**（11本すべて）
