# 制作画面：安心して試せる編集履歴と配色

対象は制作画面のみ。公開HTMLの生成、保存API、公開API、決済、独自ドメインのコードは変更しない。Claudeが確認中の初回制作導線と別のコミットとして提出する。

## できるようになること

- 文章・画像・配色・書体・ブロックの追加削除など、サイトの編集を50手まで取り消し／やり直し。
- 同じ欄の連続入力は900ms以内ならまとめる。フォーカス移動、保存、別の欄の編集で区切る。
- 一度取り消して別の編集を始めると、古い「やり直し」は消える。
- ⌘/Ctrl Z、⌘/Ctrl Shift Z、Ctrl Y。入力欄ではブラウザ自身の取り消しを奪わない。
- 5種類の配色を、写真・文章・書体・配置を保って試す。ボタン上の文字色も一緒に切り替え、読める組み合わせにする。
- 既存DESIGN_PRESETSの選択を、色と文字の見本カードに変更。カードの文字は書体分類の模式図で、正確な完成像は中央の実HTMLで確認する。
- 「大きく見る」で両側の編集欄を隠し、同じプレビューを拡大。編集に戻るボタン、親画面のEscape、プレビュー内の場所の選択で復帰する。

## 保存と境界

履歴はこの画面のメモリ内だけ。読み込み、下書きの復旧、最初のサイト生成を起点とし、その前へは戻さない。履歴自体は端末保存しない。現在の下書きの保存・アカウント照合は既存の仕組みを継続する。

取り消しはサーバの書き戻しではない。保存した後に取り消した内容は「未保存」となり、改めて保存するまで本番の保存内容には触れない。保存中に取り消しても、古い保存完了が新しい状態を「保存済み」にしない。画像アップロード中は履歴操作を無効化し、後から届いたアップロード応答との衝突を避ける。
