# 注文通知の再送

決済済み注文の保存をメール障害から分離し、運営者への注文メールを追跡可能な再送処理にした。

- 注文はStripe Webhookで先に原子的に確定する。通知失敗で決済Webhookを失敗させない。
- 通知は注文IDごとのResend冪等キーを使う。
- Resendの例外と戻り値のエラーをどちらも失敗として扱う。
- 未通知はDBで排他的に取得し、10分のリース、最大5回、23時間以内で再送する。
- 失敗理由と試行回数を注文行へ残す。23時間を超えた不確かなメールは自動再送しない。
- 本番サーバは5分ごとに内部の再送APIを呼ぶ。複数インスタンスでもDBの `skip locked` とclaim tokenで重複を防ぐ。

DB適用は `supabase/hp_orders.sql` を使う。未適用の間も注文確定は維持されるが、通知の再送は利用できない。
