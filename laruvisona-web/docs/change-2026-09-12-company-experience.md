# 会社トップの作り直し — 水滴からロゴ、そして実物へ

2026-09-12 / ブランチ `company-experience-2026-09-12`（`main` = 81026a5 から分岐）
本番反映は含みません。push・本番設定・SQL・DNS・デプロイ・本番再生成は行っていません。

## 何を作ったか

会社トップを「期待 → 実物 → できること → 支える仕組み → 相談」で一続きにしました。
冒頭は、透明な一滴が分かれて **正式ロゴの粒の配置へ整い**、透明な面がひらいて
**実際に操作できる LARU HP の出力** が現れます。

### ① 冒頭（`components/company/OpeningStage.tsx`）

- 背景は Codex 側で用意した生成画像 `public/brand/water/water-1.webp`（静止画）。
- 粒は **コードで描いています**。行き先の座標・半径は公開資産
  `public/images/laruvisona_mark.svg` をそのまま写した `components/company/mark.ts`。
  目測のトレースはしていません。仕上がりは同じ座標・同じ配色の円へ渡すので、
  ロゴとずれようがありません（検査で数値一致を確認）。
- ふつうのスクロールで進みます。ホイールの横取り・強制移動・完了までの操作不能はありません。
- 文字は透明度と少しの移動だけ。ぼかしや歪みで読みにくくしていません。

### ② 実物（`#live`）

- 中身は `components/lp/AssembleDemo.tsx`。**公開ページを作るのと同じ `exportToHTML`** が
  作ったHTMLをそのまま出しています。見せ方の3択も制作画面と同じ `DESIGN_PRESETS`。
  デモ専用の設定体系は増やしていません。
- 冒頭の「透明な面がひらく」は、この区画が実際に上へ重なってくる動きです。
  装飾の中に偽のUIを置いて、あとから別物へ差し替えてはいません。
- 「この見せ方で作りはじめる」を追加しました（`startCta`）。

### ③ 制作画面への引き継ぎ（`lib/design-handoff.ts`）

- 持っていくのは **見せ方の名前（プリセットid）だけ**。サイトの中身・お客さまの情報・
  アカウントの情報は入れません。
- ログインを挟んでも消えないよう端末に置きますが、**24時間で切れ**、
  **新しく作りはじめるときにしか読まず**（`siteId` 付きで開いたときは読まない）、
  **使ったら消します**。別のサイト・別のアカウントの設定が混ざりません。
- 制作画面側の変更は、引き継いだ見せ方を「えらぶ」の先頭に出して選択済みにするところまで。
  保存・公開・決済の処理には触れていません。

### ④ 目的から（`components/company/PurposePicker.tsx`）

- 「お店の魅力を伝えたい／問い合わせに応えたい／仕事を効率化したい」の3つ。
- 選ばなくても3件とも読めます。選んでも画面は動きません（自動スクロールなし）。
  入力を持たないので、選び直しで消えるものもありません。

### ⑤ 全体

- ヘッダー・フッターは本番の公開資産 `public/images/logo_dark.png`。仮の文字表記は置いていません。
- 暗い空間（冒頭）→ 柔らかな白（実物・できること）→ 暗い空間（仕組み・会社・相談）。
  見せ場は「冒頭」「実物へ変わるところ」「最後」。あいだは読むための余白にしています。
- 最後は、粒がもう一度ロゴへ戻って静かになります（`ClosingMark`）。冒頭と同じ座標です。
- 停止ボタンは全ページ共通（`components/company/motion.tsx`）。端末の「動きを減らす」設定では
  **最初から止まった完成状態**で、冒頭は1画面にたたまれます（動かないのに長い空きが残らない）。

## 何を使っていないか

- 金属・鉄・クロームの質感は使っていません。
- WebGL・three.js は**使っていません**。粒はSVG、動きはCSSの transform、背景は静止画です。
- 流体の物理計算はしていません。水が流れる動画も作っていません。
- 有料の生成は今回ありません。`water-1〜3.webp` は Codex 側で用意済みの素材を複製しただけです。

# 追補：品質のための作り直し（同日）

「要件を全部目立たせるより、ページ全体の美しさを優先する」という判断に合わせて、
冒頭から実物までを作り直しました。以下はその設計です。

## 一画面の主役を一つにする

作り直す前は、最初の画面で **大見出し・立体・ボタン** が同時に強く出ていました。
スマホでは大きな粒が見出しの真後ろに来て、読みにくくもなっていました。

場面を3つに分け、**片方が引いてから、もう片方を出す**ようにしています。

| 場面 | 主役 | 他は何をしているか |
| --- | --- | --- |
| 1 ことば | 見出し「まだないものを、使えるものへ。」 | 粒はまだ出さない。水の写真は暗い空気として後ろにいる |
| 2 かたち | 一滴が分かれて正式ロゴへ整うところ | 見出しは引き、一行だけが残る。写真はさらに沈む |
| 3 わたし | 画面が静かになり、実物が上がってくる | ロゴは退いて消える。文字は次への一行だけ |

受け渡しの位置は `OpeningStage.tsx` の先頭にまとめてあります（`WORD_OUT` / `FORM_IN` /
`GATHER` / `SETTLE` / `AWAY`）。動きの量ではなく、始まり・途中・終わりと、
次の場面へのつながりをここで調整します。

## 削ったもの（理由つき）

- **ひらくガラスの面（左右2枚）を削除。** 閉じているあいだ画面の中央に縦の線が出て、
  背景の写真を二分していました。「面がひらく」は実物の区画が実際に上へ重なる動きで
  足りているので、二重に描く意味がありません。あわせて `backdrop-blur` が2枚消え、
  スクロール中に32msを超えるフレームがPCで7回→0回になりました。
- **冒頭での大きな粒の常時表示をやめました。** 見出しと競っていたためです。
  粒は見出しが引いたあとに出ます。

## スマホは縮小版にしない

- パソコン：ことばは左、かたちは右（横の構図）。退くときは奥・左上へ。
- スマホ：ことばは上、かたちは下から（縦の構図）。退くときは下へ戻る。
- 置き場所はCSSの切り替えで、退く向きだけ `matchMedia` で見て変えています。

## 日本語の組み方

- 見出しは `clamp()` で画面幅に追従。折り返す位置は `<span>` で決め打ちし、
  「まだないものを、／使えるものへ。」が途中で切れないようにしています。
- 本文は読み幅を 26〜28em に絞り、`word-break: auto-phrase` を指定。
  対応する端末では文節で折り返します（非対応でも従来どおり）。
- 文字の強弱は 4段階（小見出し 10-11px / 見出し / 本文 15-17px / 注記 12px）。

## 静かに読む場面

- 冒頭（迫力）→ **「ここから先は、映像ではありません。」だけの暗い画面**（静か）
  → 実物（触る）→ **一行だけの白い画面**（静か）→ できること → 仕組み（迫力）→ 会社・相談。
- 実物の区画には水も光も持ち込みません。操作画面を覆わないためです。

# 追補：独立レビュー（8f2b9d0）への対応

`review-company-8f2b9d0/Codexレビュー.md` の R1〜R5 と D1〜D3、および検査の組み立てを直しました。

## R1 ヘッダーの行き先が存在しない

`#products` は存在しませんでした。実在する `#purpose`（事業・サービスの区画）へ変更。
あわせて、アンカー先の区画すべてに `scroll-mt` を付け、固定ヘッダーに隠れない位置へ着地させています。
検査は「IDが実在する」だけでなく「押した後、その区画がヘッダーの下に来る」ところまで見ます。

## R2 ヘッダーの「相談する」が読めない

ヘッダーに文字色の指定が無く、共通の既定色（`#171717`）のまま暗い地に乗っていました。
ヘッダー自体に `text-slate-100` を、各リンクに前景色とフォーカス表示を明示。
検査でコントラスト比を計算しています（実測 20.1:1）。

## R3 消したコピーがキーボードの順路に残る

`show()` が透明度と `aria-hidden` しか変えていませんでした。**`inert` を付けて順路から外し**、
消える場所にフォーカスが残っていたら外すようにしました。表示に戻れば `inert` も外れます。
検査は実際に Tab / Shift+Tab を押して、消えたコピーへ入らないことを見ます。

## R4 途中の停止で読んでいる場面を失う

原因は、手動停止と端末の設定が同じ処理に入り、`#opening` の高さが 320svh → 100svh へ縮んでいたことです。
**高さの切り替えを `@media (prefers-reduced-motion: reduce)` だけに結びつけ**、
手動停止では高さも配置も変えないようにしました。停止時は「完成状態へ飛ぶ」のではなく
**いま出ている姿のまま凍らせます**（`useStageProgress` の `applyOnPause: null`）。

検査では停止の前後で、ページの高さ・見出しの位置・次の区画の位置・場面（`data-act`）・
粒の座標が変わらないことを見ます。再開して続きから進むことも確認しています。
初期の静止版は、狭い画面でロゴを右下へ寄せて小さくし、冒頭のボタンと重ならないようにしました。

## R5 停止が実物デモに伝わらない

`AssembleDemo` に `motionPaused` を追加し、会社トップからは `components/company/LiveDemo.tsx` 経由で
ページ全体の停止状態を渡します。止めているあいだは分解・組立をせず、選んだ見せ方へ直接切り替わります。
**他のページ（/laruHP）では渡していないので、今までどおり端末の設定だけを見ます。**

「再開できないのに再開ボタンが出る」点は、状態の持ち方を分けて解決しました。
端末の設定で止まっているときは、押せるボタンではなく
「端末の設定で動きを止めています」という表示だけを出します（`#page-motion-note`）。
高さの切り替えがメディアクエリ側にあるため、この状態から再開しても元の場面には戻せないためです。

## D1 ロゴの主役が二重

背景の生成画像にも粒の並びが写っているため、暗くするだけでは輪郭が残っていました。
**手前の粒が主役になる前（`FORM_IN` の終わり）に、背景を画面の外へ退かせて消します**
（右へ 32%、拡大 1.34、不透明度 0）。空気は下地のグラデーションが引き継ぎます。

## D2 「実物を見る」で実物が見えない

CTA と ヘッダーの「実物を見る」の行き先を `#live-demo`（触れる枠そのもの）に変更し、
枠に `scroll-mt` を付けました。通常のスクロールでは、手前の静かな説明区画（`#live`）はそのまま残ります。
検査は「スクロール量」ではなく、**見せ方を選ぶところと作った例が画面に入っているか**を見ます
（390×844 で枠の上端 72px、選ぶところの上端 109px）。

# 追補：停止中のデモ（P2-1 / P2-2）

`a39b845` の独立確認で残った2件を直しました。今回はこの2件だけで、冒頭の構成は変えていません。

## P2-1 停止中の操作が、再開時に遅れて実行される

止めているあいだ「もう一度ばらす」を押すと、見た目は変わらないのに内部の状態だけが反転し、
再開したとたん、触っていないのに分解が始まっていました。

- 止めているあいだは、ばらす／組み上げるのボタンを**出しません**。
  押しても何も起きない操作を置くと、効かなかったはずの操作が後から効いてしまうためです。
- 押す側でも `if (motionOff) return;` で止めています（キーボード等で届いた場合の保険）。
- 止めた瞬間に、内部の状態も組み上がりへそろえます。描き直しの途中で直す書き方にしているので、
  余分な描き直しを呼びません。
- 理由は枠の下の説明に出します：
  「動きを止めているあいだは、ばらす操作を使えません。見せ方の選び直しと、中の入力はそのまま使えます。」
- **見せ方の選択と、中の入力は止めているあいだも使えます。**

## P2-2 停止後も、中で組立のアニメーションが走る

`--e` を 0 にしても、入れ物の中では 0.9 秒の transition が走り続けていました。

- 形を変える知らせに「止めているか」を**同じ一通で**渡すようにしました
  （`{ type:'explode', e, motion:'off'|'on' }`）。別々に送ると、順番によっては
  止める前に始まった動きが残ります。
- 中では `html[data-motion="off"] *{transition:none!important;animation:none!important}` を当て、
  さらに `document.getAnimations()` で**走っている途中のものをその場で終わらせます**。
- 入れ物は作り直さないので、**入力した内容は消えません**。
- 再開すると元に戻ります。
