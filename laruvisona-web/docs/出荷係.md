# 出荷係 — 本番へ上げる仕組み

最終更新: 2026-09-18

クラウド側（Claude）からは GitHub へ push できない。資格情報があるのは
Mac のターミナルだけ。そこで「最後のひと押し」だけを Mac 側の常駐に任せている。
これが **出荷係**。

```
Claude（クラウド）          Mac（出荷係）              GitHub → Vercel
  コミットを作る
  git bundle にする
  _ship/ に置く        →   launchd が気づく
                           bundle を取り込む
                           早送りか確かめる      →     push
                           done/ へ片付ける
                           _ship/state/heartbeat に脈を書く
```

## 置き場所

| もの | 場所 |
|---|---|
| 投入口 | `~/laruvisona_site/_ship/*.bundle` |
| 本番許可の印 | 同じ名前の `*.bundle.allow-main` を隣に置く |
| 記録 | `~/laruvisona_site/_ship/ship.log` |
| 脈 | `~/laruvisona_site/_ship/state/heartbeat` |
| 済み / 不調 | `_ship/done/` `_ship/failed/` |
| 本体 | `~/laruvisona_site/scripts/ship.sh` `ship-watch.sh` |
| 写し（これが正） | `laruvisona-web/scripts/ship/` |

`_ship/` は `.git/info/exclude` に入れてあり、`scripts/ship*.sh` は git の管理外。
**つまり Mac が壊れると仕組みごと消える。** だから写しをリポジトリに入れてある。
戻すときは `laruvisona-web/scripts/ship/` の2本を `~/laruvisona_site/scripts/` に置き、
`chmod +x` して、下の「取り付け」をやり直す。

## 生きているかを見る

```
cat ~/laruvisona_site/_ship/state/heartbeat
```

```
最終確認 : 2026-09-18 05:56:12
見張り   : 動いています
待ち     : 0 件
不調     : 2 件
GitHub   : 届きます (77a6794)
本番     : 反映済み a0f17b3（2分）
直近出荷 : 出荷しました: main -> a0f17b3...
版       : 2026-09-18
```

**見るのは「最終確認」の1行だけでいい。**
5分おきに書き直される。10分以上古ければ、見張りは止まっている。

`GitHub : 届きません` なら、鍵の期限切れなどで push できない状態。
bundle を置く前に分かる。

`本番` の行は、**push したコミットが実際に公開されたか**を見ている。
本番の `https://laruvisona.jp/api/health` が返すコミットと突き合わせる。
`まだ xxxxxxx（出荷は yyyyyyy・18分経過）` なら、上がってはいるが公開されていない。
15分を過ぎると通知も出る。

より詳しく見るなら:

```
~/laruvisona_site/scripts/ship.sh status
```

## 取り付け・外す

```
~/laruvisona_site/scripts/ship.sh install     # 取り付け（24時間動く）
~/laruvisona_site/scripts/ship.sh uninstall   # 外す
```

`~/Library/LaunchAgents/com.laruvisona.ship.plist` を置いて `launchctl` に読ませる。

- `WatchPaths` … `_ship/` に置かれた**その瞬間**に動く
- `StartInterval 300` … 5分おきの巡回（取りこぼしの保険）
- `RunAtLoad` … ログインしたときに1回

LaunchAgent なので、**Mac にログインしている間**動く。
再起動しても、ログインすれば自動で戻る。ログアウトすると止まる。

## 止まる道は、塞いである

過去に一度、**出荷できていないのに正常に見える**状態で止まった。
同じ止まり方をしないように、5つ手を入れてある。

1. **落ちた出荷が残した `_ship/.lock`**
   残っていると以後の巡回はすべて黙って帰る。永久に何も出荷されない。
   → 30分以上古い印は、落ちた跡とみなして外す。ログに残す。

2. **`.git` に残ったロック**（実際にこれで詰まった）
   `git fetch` が失敗し、失敗を見ずに先へ進み、**前回の ref を出荷対象にして**
   「すでに同じ内容が上がっています」とだけ出ていた。終了コードは 0。
   → 15分以上古いロックを外す。加えて `ship.sh` 側で
   fetch の失敗と、取り込んだ SHA の食い違いを、その場で止めるようにした。

3. **GitHub へ届かなくなったこと**
   鍵の期限が切れても、bundle を置くまで気づけなかった。
   → 30分に1回 `git ls-remote` で確かめ、脈に書く。届かなければ通知する。

4. **push は成功したのに、本番が入れ替わらないこと**
   出荷係は push までしか知らない。Vercel の画面を人が開くまで
   「上げたのに古いまま」が誰にも分からなかった。
   → 本番の `/api/health` に今動いているコミットを答えさせ、突き合わせる。

5. **何も言わずに終わること**
   これがいちばん悪かった。止まっているのか静かなだけなのか、誰にも分からない。
   → 走るたびに必ず脈を書く。

## 詰まったときの手順

```
cat ~/laruvisona_site/_ship/state/heartbeat     # まず脈
tail -40 ~/laruvisona_site/_ship/ship.log       # 次に記録
ls ~/laruvisona_site/_ship/failed/              # 出せなかったもの
```

`failed/` にあるものは、直したあと手で出せる。

```
cd ~/laruvisona_site
scripts/ship.sh --allow-main main
```

## 人の手が要ること

- **取り付けの確認**（`scripts/ship.sh status`）。`launchctl` はターミナルからしか触れない。
- **電源設定**。Mac がスリープすると launchd のタイマーは止まる。
  起きたときに1回動くので出荷が消えることはないが、寝ている間は上がらない。
  1週間・1年と動かし続けたいなら、ふたを閉じない・スリープしない設定にしておく。
- **鍵の更新**。GitHub の資格情報が切れたら、脈に `届きません` と出る。
