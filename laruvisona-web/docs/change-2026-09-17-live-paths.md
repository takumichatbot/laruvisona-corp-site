# 残りの導線を、本番で最後まで追った（2026-09-17）

## 追った道

### 1. 案内サイトの試作 → 制作画面（通った）

`laruhp.com` の試作（CreationLab）は、アプリ側とは**別の経路**を通る。
sessionStorage は origin ごとなので、laruhp.com では使えず、
URLフラグメントで内容を渡している。

```
laruhp.com/  「このまま制作を続ける」
  → laruvisona.jp/laruHP/continue#creation=…
  → laruvisona.jp/laruHP/studio?creation=…&step=edit
```

本番で実際に押した。**通った。**
「案内ページでつくった内容を引き継ぎました」と出て、編集画面が開く。

案内サイト側だけ壊れていた決済と同じ形（ホストで分岐する経路）だったので
真っ先に確かめたが、ここは無事だった。

### 2. 独自ドメインの設定画面（案内が手順と食い違っていた）

画面にこう書いてあった。

> 移管は不要です。**下の欄へ入力すると**、そのドメイン専用のDNS設定を表示します。

本番で入力してみたが、**何も出ない。**

コードを見ると当然だった。DNSレコードのうち所有確認のTXTは、
サーバーが発行するトークンを値に使う。**「追加」を押すまで、出しようがない。**

```ts
dnsInstructions(host, token, { expectedTarget, expectedApexIp })
//                    ↑ サーバーが「追加」のときに発行する
```

顧客から見ると、ドメインを入れて、待って、何も起きない。
**壊れていると思ってそこで止まる。** サイトを自分のドメインで公開する、
最後の一歩の画面である。

文言を手順どおりに直した。

> 移管は不要です。下の欄にドメインを入れて**「追加」を押すと**、そのドメイン専用のDNS設定を表示します。

## 中身は、よくできていた

ついでに読んだDNS案内そのものは、むしろ丁寧だった。検査で固定した。

- **配信先は A と CNAME の両方を出す。** どちらが正しいかは顧客のDNSゾーン次第で、
  片方だけ出すと置けない人がそこで詰まる。可能性の高いほうに「おすすめ」を付ける
- **`example.co.jp` を頂点だと判定できる。** ラベル数だけで見るとサブドメイン扱いになり、
  多くのレジストラで置けないCNAMEを勧めてしまう。co.jp / ne.jp / co.uk などを持っている
- **所有確認のTXTに「接続後も残してください」「既存のTXT（SPFなど）は消さずに追加」と
  書いてある。** 消されるとあとで確認が落ちる
