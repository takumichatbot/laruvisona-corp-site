# 制作体験と、できあがるサイトの品質（2026-09-12）

出す対象: `main`（`81026a5`）から分けた `laruhp-experience-2026-09-12`。
本番へは出していない（push・本番設定・SQL・DNS・本番再生成はいずれも未実施）。

やったことは3つ。
1. はじめての人の「開始 → 公開 → 直して再公開」を、実際に通して直した
2. 基準作品（結い庵）だけのCSSで成立していた品質を、全員の設定側へ移した
3. 案内ページと制作画面をつないだ

---

## 1. はじめての人の通し道

### 見つけて直した不具合

**（最大）日本語のURLのサイトが、公開しても404だった。**
`slug` は店名から作るので日本語が入る（例「のぞみ整体院-mtxb…」）。
この版の Next.js は動的セグメントを復号せずに渡すため、
`%E3%81%AE…` という名前のサイトを探しに行って必ず見つからない。
英数字だけの `slug` では起きないので、基準作品（`yuian`）では出なかった。

- 直し方: `decodeSlug()`（`lib/public-site-url.ts`）を足し、
  `/hp/[slug]` 系の6経路（本体・記事・OGP画像・sitemap・robots・ショップ）で必ず通す
- 壊れた入力（`%` 単体など）では例外を投げない。404 が 500 になるのを避ける
- 回帰: `tests/public-site-url.test.ts` に、復号の単体と
  「6経路すべてが復号してから引いている」ことの検査を追加

**偽の進捗表示をやめた。** `app/laruHP/onboarding/page.tsx` は
「ビジネス情報を解析」「FAQ・お客様の声を生成」など6段階のチェックリストを
`[700,1600,2800,4200,5600,7000]` ミリ秒の固定タイマーで進めていた。
実際の `/api/ai/generate` は1回の呼び出しで途中経過を返さない。
さらに、早く終わっても `setTimeout(3000)` で3秒待たせていた。

- 固定タイマーと3秒待ちを削除
- 出すのは「作っています…」の1状態だけ。割合は出さない
- 終わったあとに出す一覧は、**応答から数えた実数**（強みの件数、FAQの件数など）

**スマホ編集のリンクが、別のサイトを開くことがあった。**
`builder` の「スマホで編集する」が `/laruHP/edit` へ `siteId` を付けずに飛び、
`edit` 側は指定が無いと「中身のあるサイト」を自分で選ぶ。
編集中のサイトと違うものが開きうる状態だった。→ `?site=` を付ける。
まだ一度も保存していないサイトでは、リンクを押せなくする。

**「AI一括」の破壊性が見えなかった。** ボタンは「✨ AI一括」で、
既存ブロックが全部消えることは `title` 属性にしか書いていなかった。
→ 文言を「🗑️ AIで作り直す」にし、確認に**実際の削除件数**を出す。

**実装より進んだ説明文を直した。** 「SEO最適化ブログをAIが毎週自動投稿」は、
週次で走る仕組みがリポジトリに無い（ブログ画面のボタンでその都度生成する手動機能）。
ほかに「リアルタイム追跡」「継続改善」も裏付けが無く、実装に合わせて書き直した。

### 迷いどころを減らした

**公開前の確認が、画面ごとに違っていた。**
制作画面（スタジオ）は7項目、編集画面（ビルダー）はStripeと予約の重複だけ。
同じサイトでも、どちらで開くかで「準備できている」の意味が変わっていた。
→ `lib/publish-readiness.ts` に寄せ、両方から同じ関数を呼ぶ。
段階は2つだけにした。

| 段階 | 意味 |
|---|---|
| `must` | 直さずに公開すると、来た人に実害が出る（連絡が届かない／購入ボタンが出ない／例文が公開される） |
| `better` | 直したほうが良いが、公開できないほどではない |

「4/7」のような割合は出さない。重さの違うものを同じ1として数えてしまうため。

**保存できない理由が、作り終わってから出ていた。**
契約が無い状態で保存すると `no_plan` で断られる。ここまでの入力が消えるのが怖い。
→ 保存前の下書き（4つの質問と組み上がった中身）を、この端末に控える。
ログイン切れ（401）と契約なし（403）は帯で理由と行き先を出し、
戻ってきたら続きから直せるようにした。未保存のまま閉じようとしたら確認も出す。

**新しいサイトの入口が3つあって、制作画面はどこからも行けなかった。**
案内ページは `/laruHP/studio`、ダッシュボード初回は `/laruHP/onboarding`、
2件目以降は空の `builder` 直行。ログイン後の利用者はスタジオに辿り着けなかった。
→ ダッシュボードの「新しいサイト」も、初回の入口もスタジオへ。
中身が空のサイトを開いたときは、空の編集画面ではなく4つの質問から始める
（答えたあとは、そのサイトにそのまま書き込む。新しい行は作らない）。

### 通し確認（実ブラウザ）

`tests/browser/first-run-check.mjs`。美容室ではなく**整体院**で、
案内ページ → 見せ方を選ぶ → 制作画面 → 4つの質問 → 雰囲気 → 編集 →
スマホ確認 → 保存 → 公開 → 公開URL表示 → 直して再公開、を実際に押して通す。
**24/24 通過。**

書体は顧客が選んだものを実際に読み込ませている（`tests/browser/_local-fonts.mjs`）。
この環境は Google Fonts へ出られないので、同じ書体のファイルを手元から配り、
`fonts.googleapis.com` への要求だけを差し替える。ページ側のコードは変えない。

## 2. 結い庵だけのCSSを、全員の設定へ

`docs/reference-sites/salon/site.json` の `customCss` は **2,410字 → 1,227字**。
減ったぶんは、全利用者の生成側へ移した。

| 移したもの | どこへ |
|---|---|
| 既定CSSに残っていた青（`#2563eb`）11か所 | `var(--lhp-accent,#2563eb)` に統一。差し色を設定した店はその色になり、設定していない店はこれまでと同じ |
| 予約ブロックの日付・時間ボタンの色（JSで直書きしていた） | クラス（`lhp-bk-btn` / `lhp-bk-sel`）に変え、CSS側で決める。customCss から上書きできる |
| スタッフの丸写真の大きさ | インラインstyle固定をやめ `lhp-team-photo` クラスへ。余白が `roomy`/`airy` のときは148px、それ以外は120px（既定CSS側は96pxのまま） |
| 料金明細・お客様の声・カードの本文 | `designCss()` の本文セレクタに追加（抜けていた） |
| よくある質問・営業時間の読み幅 | `--lhp-d-read` を使う（720px/400px固定だった） |
| 金額の文字の大きさ | `headingScale` に連動（2.2rem固定だった） |
| スマホでのヒーロー写真の切り抜き | 設定を使う店は768px以下で3:4（4:3固定だった） |
| ヒーロー中央の飾り線の色 | `ink` 由来に（明るい地で消えていた） |
| 画面下固定ボタンの下の余白 | 二重に空いていたのを詰めた |

**見つけて直した品質の不具合。**「おすすめ」の料金カードのボタンが、
サイト全体の設定を使うと**白地に白文字で消えていた**。
既定CSSは「おすすめの札は差し色の地」を前提に中のボタンを白地にしているが、
設定を使うと札の地は明るい面になるため。ほかのボタンと同じ「差し色の地＋その上の文字色」にそろえた。
結い庵は `.lhp-price-featured *{color:… !important}` でこれを覆い隠していた。

`EXPORT_VERSION` は 11 → **12**。

**互換性。** 見え方が変わる改善は、`settings.design`（サイト全体の設定）を
持つサイトにだけ出る `designCss()` 側に置いた。設定を持たない古いサイトは、
スタッフ写真96px・ヒーロー写真4:3・読み幅720px のままで、生成結果は変わらない。
色は必ず `var(--lhp-accent, #2563eb)` の形にして、差し色を設定していない店は
これまでと同じ青のままにしている。回帰テストで両方を固定した。

**別の業種でも同じ品質が出るか。** 上の通し確認（整体院）を、通常の制作・保存・
公開の経路だけで行っている。スマホで横にはみ出さないこと、公開HTMLに
直書きの青が残っていないこと、選んだ書体が実際に読み込まれることを確認した。

## 3. 案内ページと制作画面をつなぐ

案内ページのデモで選んだ見せ方が、そのまま制作画面へ引き継がれる。

- デモの下に「この見せ方で作りはじめる」を置き、`/laruHP/studio?mood=<id>` へ
- 持っていくのは `DESIGN_PRESETS` の id ひとつだけ（別体系は作らない）
- 制作画面の「えらぶ」で、その見せ方を先頭に出して印を付ける。選び直しは妨げない
- ログインや契約を挟んでも消えないよう、この端末に控える

会社トップの主役ビジュアルは採用済みのものを維持、結い庵はB案のまま。動画は待っていない。
