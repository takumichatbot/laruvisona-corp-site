# 契約者がぶつかる行き止まりを、まとめて直した

2026-09-17

公開している文章の点検（第1弾・第2弾）に続いて、**契約者が実際に使う画面**を洗った。
「押しても何も起きない」「保存できていないのに成功に見える」「無言で失敗する」が中心。

## 直したもの

### カレンダーが丸ごと死んでいた

`/laruHP/calendar` は `/api/posts` を呼んでいたが、**そのAPIは存在しない**（あるのは
`/api/posts/[postId]` と `/api/sites/[id]/posts`）。404のHTMLをJSONとして読もうとして
例外になり、catch も無いので**空のカレンダーが出るだけ**だった。

さらに、下書きを日付にドラッグすると `scheduled_at` を送っていたが、この列は
DBにもAPIにも無く、リロードで消えていた。仮に保存できても、その日に公開する仕組みが無かった。

- 一覧は `/api/sites/{id}/posts?all=true` から読む。失敗は画面に出す
- 予約は `scheduled_at` 列で持つ（`supabase/news_posts_scheduled.sql`）
- `app/api/cron/publish-scheduled` が予約時刻を過ぎた記事を公開する。`server.js` から10分ごと
- 日付だけだとUTCの0時＝日本時間の前日朝になるので、その日の9時に公開する
- 列がまだ無い環境でも落ちない（応答に「SQLを実行してください」と出す）

**published_at では代用できない。** 下書きにも `published_at` が入る（default now()）ため、
それで判断すると出すつもりのない下書きまで公開してしまう。

### 保存が失敗しても成功に見えていた画面

| 画面 | 何が起きていたか |
|---|---|
| ブログ | 保存・削除・公開切替が `res.ok` を見ず、モーダルを閉じていた。**書いた本文が消える** |
| SEO設定 | 保存失敗 → 再公開成功で「反映されました」と表示。古いSEOのまま公開 |
| CRM | 状態変更・メモ・期限がリロードで元に戻る |
| かんたん予約 | 枠を一括追加しても、保存できていなければ公開サイトに出ない |
| エージェンシー | ブランド設定・顧客情報が「✓ 保存しました」なのに戻る |

いずれも、保存できたときだけ画面を進めるようにし、失敗は理由を出す。

### 無言で失敗していたもの

- **AIサイト診断**: 403（契約）・429（回数上限）・500 を「データ無し」に潰していたため、
  何度押しても同じ画面に戻るだけだった。理由を出す
- **問い合わせの通知メール**: `RESEND_API_KEY` 未設定だと、訪問者には「送信が完了しました」、
  契約者にはメールが届かない。問い合わせ詳細に `owner_email_status / not_configured` と
  英語のキーが並ぶだけだった。日本語にして、届いていないことを警告として出す
  （問い合わせ自体はDBに残っているので、その旨も書く）
- **ショップの決済が停止中でも、客はレジまで進んで `alert` で終わっていた**。
  公開HTMLを作る時点で決済の可否は分かるので、停止中は購入ボタンを出さず、理由を書く
- **事前決済の設定欄ごと消えていた**（使えない環境では存在しないように見えた）。
  欄は出して「順次提供の準備中」と書く
- **ステップ配信が送れているか画面から分からなかった**。送信済みの通数と最終送信時刻を出し、
  登録があるのに0通なら警告する

### 多言語翻訳が、公開ページに反映されていなかった

「英語への翻訳が完了しました（142件）」と出て、案内されたURL（`/hp/<slug>?lang=en`）を
開くと**日本語のページが出ていた**。しかもそのURLを sitemap で検索側へ送っていた。

- そもそも翻訳の抽出が `block.props` / `block.children` を見ていた。このアプリのブロックは
  `{ id, type, data }` で、複数ページは `{ v:2, pages }`。**集まる文章がほぼ空だった**
- `lib/translate-apply.ts` を追加。公開HTMLの**テキストの節だけ**差し替える。
  属性・スクリプト・スタイルには触らない。訳文はエスケープしてタグを注入させない
- `?lang=` を読むようにし、`alternates.languages`（hreflang）も出す

### 押しても目的地に着かないリンク

- ダッシュボードの「Search Console を連携しよう → 設定する」が `?section=gsc`。
  設定画面が読むのは `tab` と `gsc`。連携欄は `integrations` タブの中なので、
  既定のアカウントタブが開くだけだった → `?tab=integrations#gsc`
- アクセス解析の「Search Console →」も同じ
- ヒートマップ0件の案内「公開サイトにトラッキングスクリプトを追加してください」は**誤り**。
  計測タグは公開時に自動で入る。リンク先の `?tab=settings` もビルダーは読んでいない
  → 文言を実態に合わせ、リンクを外した
- 問い合わせ一覧の絞り込みが `?siteId=`。受け側が読むのは `?site=`。
  「そのサイトの問い合わせ」を押しても全件が出ていた（ダッシュボード・エージェンシー計3か所）

### そのほか

- Google連携ボタンのアイコンが **Discord のロゴ**だった → Google の G に
- `GEMINI_API_KEY` 未設定時に「Google AI API key not configured」と英語で出ていた → 日本語に
- 制作スタジオの「← 一覧」が未保存でも確認なしで抜けていた（予約管理へのリンクには確認がある）
- スマホ（390px）で会員・登録者・ブログ一覧の操作列が押せなかった（`overflow-hidden` で
  横スクロールごと封じられていた）→ `overflow-x-auto`
- 料金比較表が390pxで5列のまま潰れていた → 横スクロールと最小幅
- エージェンシー管理を非対象プランで開くと**無言で料金ページへ飛んでいた** → 理由を出す

## 実行が必要なSQL（1回だけ）

予約投稿の列を追加する。Supabase の SQL エディタでそのまま実行できる。

```sql
alter table public.news_posts add column if not exists scheduled_at timestamptz;
create index if not exists news_posts_scheduled_idx
  on public.news_posts (scheduled_at) where published = false and scheduled_at is not null;
```

実行するまで、カレンダーの予約は「まだ使えません」と表示される（壊れはしない）。

## テスト

`tests/translate-apply.test.ts`（8件）。属性やスクリプトを訳さないこと、訳文からタグを
注入できないこと、公開ページが `?lang=` を読むこと、抽出が今のブロック構造を見ていることを固定。

`EXPORT_VERSION` 19 → 20（ショップの決済停止表示）。公開済みサイトは次の公開か再生成で反映される。
