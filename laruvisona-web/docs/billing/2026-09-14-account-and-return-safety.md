# 契約決済・退会・戻り先の安全化（2026-09-14）

## 直したこと

- Stripe Checkout と請求ポータルの戻り先は、リクエストの `Origin` ではなく運営側で固定したアプリ origin から作る。
- 既存契約を Stripe で確認できないときは、新しい Checkout を作らない。二重契約を防ぐ。
- DBの契約IDが欠落・古い場合も、同じStripe顧客に有効な契約が残っていれば新規契約を作らない。
- Checkoutセッションにも利用者・プラン・請求周期単位の idempotency key を付ける。
- サイトIDを決済に含める場合は、形式と本人所有を確認したIDだけを使う。
- Stripe の契約変更後と顧客作成後は、プロフィールを実際に1件更新できたことを確認する。
- Stripe 顧客の作成には利用者単位の idempotency key を付ける。
- 最低契約期間中の請求ポータルは、カード変更だけの単一フローにする。期間終了後は通常の管理ポータルを開く。
- Stripe顧客に有効な契約が1件でも残る利用者は退会させない。Stripe を確認できない場合も削除へ進まない。
- 退会は `auth.users` の削除を起点にし、外部キーの cascade で所有データを削除する。削除失敗を成功として返さない。

## 確認

`tests/billing-safety.test.ts` と `tests/stripe-subscription-sync.test.ts` で、固定した戻り先、既存契約確認失敗時の停止、更新件数、退会の順序、最低契約期間中の支払方法限定フローを確認する。

本番では Checkout、請求ポータル、Webhook、退会を Stripe のテストモードで1回ずつ通し、Stripe と `profiles` の状態が一致することを確認してからライブ決済を開放する。
