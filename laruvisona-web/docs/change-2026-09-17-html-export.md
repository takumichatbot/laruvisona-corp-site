# 書いた記事の約束を、本当にできるようにした（HTML書き出し）

2026-09-17

## きっかけ

同じ日に公開した記事 `hp-tool-hikaku` に、こう書いていた。

> 公開したページはHTMLとして書き出せます。

書いたあとで確かめたら、**できなかった**。

- 設定画面の「データのエクスポート」は **JSON**（サイト設定と問い合わせ履歴）だけ
- `exportToHTML()` は存在するが、使っているのは公開処理とプレビューの中だけ
- お客さまが自分でHTMLファイルを受け取る導線は、どこにもなかった

記事のもう1か所（`hp-getsugaku-ikkatsu`）では「HTMLとして書き出せるかを、始める前に確認してください」と、
**他社を選ぶときの判断基準**として書いている。その基準を自分が満たしていなかった。

## 直し方

文章を消して逃げることもできたが、機能のほうを作った。判断基準として正しいと思って書いたものなので。

### 1. `lib/site-export.ts`（新規）

- `pagesFromBlocksJson()` — 保存形式 v1（`Block[]`）と v2（`{v:2, pages}`）の読み分け。
  公開処理にも同じ読み分けが手書きで入っていたので、**公開と書き出しの両方がここを通る**ようにした。
  2か所に分かれていると、いつか「公開はできるのに書き出せない」がおきる。
- `portableSettings()` — 書き出すHTMLからは larubot と LARU SEO の埋め込みを外す。
  外へ持って出るためのファイルなので、こちらのサーバーへ繋ぎにいく部分は入れない。
  お客さま自身のGA計測IDは、お客さまのものなので残す。
- `exportFileName()` — 日本語の屋号でも壊れないファイル名（ASCII控え名 + `filename*` のUTF-8名）。

### 2. `app/api/sites/[id]/export-html/route.ts`（新規）

GET。ログイン必須、`user_id` 一致のサイトだけ。1枚のHTMLとして `Content-Disposition: attachment` で返す。

**契約状態では止めていない。** 文章と写真はお客さまのものなので、解約したあと・支払いが
止まったあとでも取り出せる必要がある。ここに `hasServiceAccess` を入れると、
「やめたら持ち出せない」になり、記事に書いた約束と逆になる。

### 3. 設定 → データのエクスポート に導線を追加

「ページをダウンロード (HTML)」。合わせて、できないことも先に書いた。

> お問い合わせフォーム・予約・ショップ・会員ページなどLARU HPの機能は、このファイル単体では動きません
> （文章・写真・デザインはそのまま残ります）。

### 4. 記事の文章も正確にした

どこから書き出すのか、何が動かないのかまで書いた。「書き出せます」だけだと、
フォームごと動くと読める。

## 確かめたこと

- 書き出したHTMLを実ブラウザ（file://）で表示 → 見出し・本文・フォームの見た目が出る。JSエラーなし。
- 書き出したHTMLに `larubot.tokyo` の埋め込みが**入っていない**こと。
- `tests/site-export.test.ts`（8件）— 保存形式2種、埋め込み除去、ファイル名、
  ルートの本人確認、公開と書き出しが同じ読み方を通ること、
  **記事の文章に対応する画面が実在すること**。

最後の1件が本題。記事で約束したことが実装から消えたら、テストが落ちる。

## 残っていること

- og:image だけ `laruvisona.jp/api/og?...` を指したまま（画像生成の入口）。表示は壊れないが、
  完全に独立させるなら画像を同梱する必要がある。いまは見送り。
