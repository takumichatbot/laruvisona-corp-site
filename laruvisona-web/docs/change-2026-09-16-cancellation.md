# 自分で解約できない状態を直す（2026-09-16）

## 約束していたこと

利用規約 第4条、および特定商取引法に基づく表記に、こう書いてある。

> 最低利用期間（6ヶ月）の途中では解約できません。
> **7ヶ月目からは月単位でいつでも解約できます。**
> 解約申請はダッシュボード内の「サブスクリプション管理」…にて承ります。

## 実際に起きていたこと

契約中は、**いつまで経っても解約画面が開かない。**
「サブスクリプション管理」を押すと、カードの変更画面しか出ない。

## 原因

`app/api/stripe/portal/route.ts` が、最低利用期間の判定に
`contract_ends_at` を使っていた。

```ts
if (profile.contract_ends_at && profile.subscription_status === 'active') {
  if (new Date(profile.contract_ends_at) > new Date()) paymentMethodOnly = true;
}
```

ところが `contract_ends_at` は「最低利用期間の終わり」ではなく
**「いまの請求期間の終わり」**で、支払いのたびに翌月末へ更新される。

```
webhook/route.ts:186  contract_ends_at = sub.current_period_end     … 契約時
webhook/route.ts:246  contract_ends_at = 最新invoiceのperiod.end     … 毎月の支払いごと
```

契約している限り、この日付は常に未来。だから
**7ヶ月目になっても、10ヶ月目になっても、永久に解約画面が開かない。**

買う前に特商法を読む人は、守られていない約束を見つけることになる。

## 直したこと

最低利用期間の終わりを、契約の**始まり**から数えるようにした。
純粋な関数として切り出し、検査を書いた（`lib/billing-portal-mode.ts`）。

```ts
minimumTermEndsAt(contract_starts_at) = contract_starts_at + TERMS.minimumMonths
```

- 期間中: 支払方法の変更のみ（従来どおり）。あわせて、いつから解約できるかを返す
- 期間後: 通常の管理ポータル（解約できる）

## 黙って飛ばさない

これまでは、期間中でも無言でStripeのカード変更画面へ飛ばしていた。
解約が見当たらない理由が分からないので、**解約させない作りに見える。**

ダッシュボードで、進む前に理由と期日を出すようにした。

> 最低利用期間（6ヶ月）の途中のため、いまは支払方法の変更のみ行えます。
> 2026/7/15 から、この画面で解約できます。
> それより前の解約のご相談は info@laruvisona.jp へどうぞ。

規約には「メールでも承ります」と書いてあるので、その窓口も併記した。

## 確認したこと

- `tsc` / `eslint`: エラーなし
- `npm test`: 833 passed（`tests/billing-portal-mode.test.ts` を新規に5件）
  - 最低利用期間は契約の始まりから数える
  - 期間中だけ支払方法に絞る
  - **7ヶ月目からは解約できる（以前は永久に開かなかった）**
  - 未契約・解約済みは通常のポータル
  - 請求期間の終わりで判定していないこと（再発防止）
- `next build`: 成功

## 残っていること

Stripe側のポータル設定で解約が有効になっているかは、こちらからは確認できない。
**本番で一度、実際に管理ポータルを開いて、解約の項目が出ることを確認する必要がある。**
