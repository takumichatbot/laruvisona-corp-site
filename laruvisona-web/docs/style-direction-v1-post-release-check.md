# 見た目の3案（Style Direction v1）出荷後の確認手順（運営の専用テストサイト1件）

出荷承認・本番反映のあとに、**運営が持つ専用テストサイト1件だけ**で行う。実顧客のサイトは使わない。
本番での一括再生成（`/api/admin/republish-all` の実行・`REPUBLISH_ON_BOOT=1`）はこのリリースでは使わない。
dryRun が要るときも、専用テストサイトの slug を指定した1件だけにする。

## 0. 前提の確認（読み取りだけ）

- Render の本番サービス（laruvisona-corp-site / `srv-d8oq30ho3t8c73dvj3gg`、独自ドメイン laruvisona.jp ほか）の
  Environment に `REPUBLISH_ON_BOOT` が無いこと。環境グループの連携が無いこと。
- 反映後の起動ログに `[republish] 起動時の一括再生成はしない` が出ていること。
- どちらかが確かめられなければ、ここで止める。設定の変更・再起動はしない。

## 1. 開始前の控え（専用テストサイト）

所有者としてログインし、次を手元のファイルに控える（秘密の値はファイルにもチャットにも書かない）。

| 控えるもの | 取り方 |
| --- | --- |
| 下書き（name・blocks_json・seo_json・settings_json） | `GET /api/sites/<id>`（所有者のログインで）の応答 |
| 公開状態（公開中か） | 同上の `published` |
| 公開HTMLの指紋 | 同上の `published_html` の SHA-256（中身は保存しておく。書き戻しには使わない） |
| 公開ページの head | `/hp/<slug>` の `<title>`・description・og:title・og:description・og:image・twitter:*・構造化データ |
| 公開ページの見た目 | PC 1440 とスマホ 390 のスクリーンショット |

## 2. 採用して保存しただけの段階（公開しない）

1. Studio で「写真で惹きつける」を比較 → 要約・詳細・配色・個別色の表示を確かめる → 採用 → 保存。
2. **同じ画面のまま**「取り消す」1回で採用前に戻ること、「やり直す」で採用後に戻ることを確かめる（同一セッションの Undo の確認）。
   採用後の状態にして保存する。
3. 再読み込み → 案・配色・色の役割・動きが残っていることを確かめる（保存復元の確認）。
   **再読み込みのあとは Undo の履歴が残っている前提にしない。**
4. 公開操作をしていないので、次が開始前と**完全に同じ**であること：
   - 公開HTMLの指紋（`published_html` の SHA-256）
   - 公開ページの head（title・description・og・twitter・構造化データ）
   - 公開ページの本文
5. 専用テストサイトの slug だけで dryRun：`{"slug":"<slug>","dryRun":true}` → `plan` が `unpublished_changes` であること（書かない）。

## 3. 公開して確かめる段階

1. 公開 → `/hp/<slug>` を PC・スマホで確かめる（案が出る・本文・head が採用後の内容）。
2. Safari（Mac）と iPhone 実機で、公開ページの表示と、Studio の比較を開く → 選ぶ → 採用 → 取り消しの代表経路を確かめる
   （開発環境では未確認のため、ここで行う）。

## 4. 元の内容へ戻して再公開する段階

1. 控えた下書き（1 の name・blocks_json・seo_json・settings_json）を、**通常の所有者用の保存経路**（`PUT /api/sites/<id>`）で書き戻す。
   DB へ公開HTMLを直接書き戻すことはしない。
2. 開始前に公開中だったなら公開、非公開だったなら非公開へ戻す（所有者の公開・非公開の操作で）。
3. 確かめること（公開HTMLの**バイト単位の完全一致は求めない**。EXPORT_VERSION 21→22 と承認済みの共通修正があるため）：
   - 本文・画像・リンク・フォーム・設定が開始前の内容へ戻っている（`GET /api/sites/<id>` が控えと一致）
   - 公開HTMLが、**今の書き出し（exportToHTML）で控えの元データを描いた期待結果と一致**する
   - 開始前の公開HTMLとの差分が、承認済みの共通修正（`:root` の変数の区切り、ミニマルの問い合わせ見出し、
     公開時点の補足 `<!--lhpmeta-->`、版の印 `lhpv:22`、SEO設定画面のOG画像の焼き込み）などに限られている
   - 公開ページの head の title・description・og・twitter が開始前と同じ値
   - 構造化データ：開始前が以前の公開HTML（`<!--lhpmeta-->` なし）で、公開時点の事業者情報を確かめられなかった場合は、
     再公開で事業者情報が付くことがある（公開時点の値として焼き込まれるため。承認済みの変更）
4. 公開状態が開始前と同じであること。

## 5. 記録

各段階の結果（指紋・head の値・スクリーンショット・dryRun の応答）を残す。本番で一括再生成は実行しない。
