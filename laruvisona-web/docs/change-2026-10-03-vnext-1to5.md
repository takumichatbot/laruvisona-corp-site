# 見た目を言葉・参考・見直しで整える／会社の情報を使い回す（vNext 1〜5）

基準：開始 = main 590c74f。途中で別作業の 94db677（LARU CALL への導線。Studio と重ならない）が main に入ったため、
その上に載せ直して出荷（37b3cc4、早送り）。

## 何ができるようになったか

| | 入口 | 中身 |
|---|---|---|
| 1 言葉で直す | Studio「サイト全体」→「言葉で直す」 | 「もう少し落ち着いた印象に」などを、決まった言い回しで1つの計画にする。今の値から一段だけ。範囲はサイト全体／選んだ節（「この節」と書くと選んだ節）。読めない言い回しのときだけ AI が意図（19種類から最大3つ）を選ぶ |
| 2 参考画像から | 同「参考画像から」 | 画像を端末の中で縮小し、明るさ・色の強さ・余白・線の多さ・写真らしさの数値だけを読む。送信・保存・サイト素材化はしない。書体・動きは「判断しない」と表示 |
| 3 公開前の見直し | 同「公開前の見直し」／「公開の準備」の「見た目も見直す」 | コードの確認（色の差・最初の画面のボタン・長い見出し・写真の説明・長い文章・横にはみ出す英数字・中身の無い節・電話番号の食い違い・動きの量・文字だけの節の連続・サイト全体の設定の有無）。公開の準備と同じ判定は件数で案内するだけ。「今直す」「直すと良い」「問題なし」、点数なし。AI の見立ては任意（決まった7種類から選ぶだけ） |
| 4 会社の情報 | 同「会社の情報」 | settings_json.businessFacts（対応地域・ひとこと・来てほしい人・主なサービス・連絡のしかた）。最初の質問で本人が打った答えを控える。保存のみで公開HTML・JSON-LD・lhpmeta には出さない。見本のままの文章欄に「この情報をここにも使えます」（変更前・後を見せてから入れる）。「AIに相談」には関係する情報だけを入れるボタン |
| 5 表現 | 上の3つの計画 | 既存の設定だけ（余白・見出し・書体・角・ボタン・写真の比率・最初の画面の配置・写真の並べ方・現れ方・動きの強さ・配色5種）。新しい描画の仕組みは足していない |

## 共通の決まり（lib/design-change.ts）

- 3つとも同じ「変更計画」を作り、比較と採用は同じ関数（applyDesignPlan）。採用は1回の setSite＝取り消し1回
- 許可リストの外（文章・リンク・電話・料金・フォーム・customCss・通知先など）は計画に入らない
- 計画を作ったあとに同じ欄が変わっていたら当てない（古い案で上書きしない）
- 最初の画面の配置を変えるとき、文字の色を配置に合わせる（写真の上は白、左右に分けるとサイト全体の文字の色、
  見た目の案を採用済みで見本写真のままなら地の上なので文字の色）。見本写真のままなら写真の上に文字を重ねる組み方にはしない
- 出どころ：名前＝sites.name／業種＝sites.industry／電話・住所・営業時間＝businessInfo（検索・SEO。Studio では見るだけ）／
  そのほかの事実＝businessFacts

## AI の呼び出しと費用

- 複数の指示のうち、すでにその方向の端にあるものは「変えません」と確認画面に出す（黙って落とさない）
- 言葉で直す：決まった言い回しで読めたときは呼ばない。読めないときだけ1回（同じ指示は呼び直さない）。渡すのは指示文だけ。max_tokens 120
- 公開前の見直し：押したときだけ1回（同じ状態は呼び直さない）。渡すのは節の種類・文字数・写真の枚数・見た目の設定だけ。max_tokens 120
- 参考画像：AI を使わない（費用0）
- 契約判定は「AIに相談」と同じ（lib/studio-ai-gate.ts）。利用回数は 20回/時・10回/時
- 実モデル（claude-haiku-4-5-20251001）での読み取りの質：**未確認**（試験用の鍵なし。偽DBの保存済み応答でだけ確認）
