## 先に確かめたこと

向こうの文書を鵜呑みにせず、こちらのコードで3点を確認した。

### 認証ヘッダーの食い違いについて

向こうの修正前の実装は `X-LARU-HP-Secret` を見ていた。`hp-` の有無だけの違いだが、
**名前が違えばヘッダーは見つからない**ので、こちらからの登録はすべて401で弾かれていたことになる。

こちらは応答本文を捨ててステータスしか見ておらず、失敗しても決済は止めない作りなので、
「課金は通ったのにボットが作られない」がどこにも出なかった。

**実害の確認**: 本番の Stripe に契約は0件（`GET /api/cron/subscription-sync` の空打ちで `scanned: 0`）。
つまり**この経路を通った本物の契約はまだ無い**ので、取りこぼした顧客はいない。
向こうが両方の名前を受けるようにしたため、こちらの送り方は変えていない。

## 直したもの

### 1. 応答本文を読む（`lib/larubot-provision.ts`）

`public_id` は**最初から応答に入っていた**。こちらは `res.body?.cancel()` で捨てていたので、
LARUbot からのコールバックが来るまで紐付けが終わらなかった。コールバックが落ちれば永久に付かない。

本文を読み、その場で `settings_json` へ書き込むようにした（`linkLarubotIds`）。
コールバックが後から来ても同じ値で上書きされるだけなので、二重にはならない。

受け取った値は `[A-Za-z0-9_-]{1,64}` で確かめてから使う。よそから来た文字列を、
そのまま設置タグに入れない。

### 2. `agency` をそのまま送る

`hp-bot` に変換していた。向こうでは `hp-bot` に LARUSEO が付かない。
**全機能込み（HP + LARUbot Lite + LARUSEO）として月額19,800円で売っているのに、
LARUSEO が付いていなかった。** 向こうは `agency` を受けるようになったので、変換をやめた。

### 3. `site_id` は、値が無いときキーごと省く

空文字を送っていた。向こうはそれをそのままこちらの webhook へ転送し、
こちらは `invalid site_id` で400にして、何も紐付かない。往復して何も起きない状態だった。

### 4. 失敗の理由を、機械で判定できる形にする

`LarubotRegisterError` に `code`（`unauthorized` / `email_required` / `invalid_plan`）を持たせた。
これまでは画面に一律「登録に失敗しました」としか出せなかった。

### 5. 無い上限を売るのをやめた

料金ページの「**設置ボット数 lite 2体 / hp-bot 3体**」に対応する上限は、
**LARUbot 側のコードに存在しない**。1アカウント=1ボットで、設置タグは何サイトに貼っても動き、
サイト数の制限も無い。2体/3体 の数字は「チャット内のメニュー項目数」のものだった。

「チャット内のメニュー項目 2件 / 3件」に書き換えた。ダッシュボードのプラン説明にも
同じ文言があったので、そちらも直した。

Q&A 登録数（15件 / 30件）と質問例（3件 / 5件）は、向こうが料金ページに合わせて実装を直した
（修正前は hp-bot が10件で、しかも画面には30と出ていた）。**料金ページはそのままでよい。**

## まだやっていないこと

- **`requestIdleCallback` の差し替えと `blog.js` の動的注入の回避を外す。**
  向こうは直したと言っているが、外す前に実際にランチャーと記事が出ることを確かめる必要がある。
  確かめずに外すと、出なくなったことに気づけない。
- **`/blog` `/blog/[slug]` のサーバー側描画。** 口はすでにある
  （`/api/seo/public/<public_id>/articles` と `/api/seo/public_article_data/<public_id>/<slug>`）。
  いまは記事の本体が1文字もこちらのHTMLに入っていないので、検索の評価が向こうに乗る。
- **`laruseoPublicId` を別枠で持つのをやめる。** 向こうの回答では
  チャットと LARUSEO は同じ `public_id`。別の値を入れる欄が残っていると、
  設置タグに違う値が入って記事が0件になる。
- **会話ログ（`/api/larubot/conversations`）。** 向こうはまだ送っていない。
  送る前に、対象範囲・頻度・会話本文をこちらに置いてよいかを決める必要がある。急ぎではない。
