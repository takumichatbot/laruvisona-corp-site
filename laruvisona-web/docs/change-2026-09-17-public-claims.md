# 公開している「できます」を全部、実装と突き合わせた（第1弾）

2026-09-17

## きっかけ

同じ日に、記事に書いた「HTMLで書き出せます」が実装に無いことが分かった（`change-2026-09-17-html-export.md`）。
1件あるなら他にもある前提で、購入前のお客さまが読む文章を全部洗い出した。

対象: LARU HPのLP・料金・ドメイン・デモ・規約・特商法・記事11本・業種ページ15本、
会社サイトのトップ・サービス・実績・構造化データ。

**検証可能な断定 53件のうち、FALSE 15件・PARTIAL 24件。**

多かったのは「実装に無いことを売っている」だけではなく、**「できるのに、できないと書いている」**ほう。

## 直したもの

### 売っているのに使えない

**エージェンシー（¥19,800／「全機能込み」）が LARUSEO を有効化できなかった。**
`app/laruHP/builder/page.tsx` のプラン判定が `userPlan === 'hp-bot-seo'` の直書きで、
agency が漏れていた。課金済みの人に「HP + Bot + SEO プランにアップグレード →」と出る。
API（`app/api/ai/blog-generate`）は agency を許可していたので、実装同士も食い違っていた。
→ `hasFeature(userPlan, 'seo')` に統一。

**メールシーケンスのプラン差（hp:− / lite:3件 / hp-bot:5件）が実装に存在しなかった。**
`app/api/sequences/route.ts` にプラン判定も本数の上限も無く、どのプランでも無制限に作れた。
→ `PLAN_SEQUENCE_LIMIT` を `lib/plan-limits.ts` に置き、作成時に見る。
すでに上限を超えて持っている人からは取り上げない（増やせないだけ）。

### 金額・法定表記

**記事の「最低6ヶ月＝5,994円」が初月無料を計算に入れていなかった。**
実際に払うのは5ヶ月分＝4,995円。3年総額の35,964円も同じ誤り（正しくは34,965円）。
自分のサービスを999円高く見せていた。

**「初月無料」のクーポンが本当に無料にするのかを、誰も確かめていなかった。**
全プランで同じクーポン1枚を使っている。固定額（例999円オフ）だと、HP単体は無料でも
エージェンシーは18,801円請求される。価格の照合（`lib/price-integrity.ts`）は
**金額しか見ていなかった**ので、この食い違いは見つからない。
→ `verifyFirstMonthCoupon()` を足し、決済を作る直前に見る。割合100%でないプランには売らない。
管理画面の `price-check` も set/未設定ではなく中身を返す。

**特商法の表記が HP単体・月払いだけだった。** 実際は5プラン（¥999〜¥19,800）と
年払い（最大¥198,000）を売っている。→ `PLANS` から全プラン＋年払いを生成。
規約の第3条にも年払い（一括・途中返金なし）の条項を追加。

**`lib/laruhp-facts.ts` の PLANS に lite と agency が無かった。**
契約条件の「正」から2プランが漏れていた（LPの構造化データの価格帯も3プラン分だった）。
→ 5プラン全部を持ち、LPは `landing: true` の3つだけ出す。表示する場所と正本を分ける。

### できるのに「できません」と書いていた

業種ページのよくある質問で、**実装済みの機能を5か所で否定していた**。

| 業種 | 書いていたこと | 実際 |
|---|---|---|
| 美容室 | 「空き状況はリアルタイムで出せません」 | 出せる。スタッフ・設備の重複まで見る |
| 飲食店 | 「予約の確定まで自動は標準ではない」 | できる。枠を選んでその場で確定 |
| 士業 | 「日程の自動確定は別の仕組みと」 | できる |
| ウェディング | 「見学予約の自動確定は別途」 | できる。会場と担当者の両方を見る |
| フィットネス | 「会員管理は公開サイト側の機能ではない」 | 会員登録・有料会員・限定ページまである |

売り物を自分で小さく言っていた。ホテルの客室在庫は本当に無いので、そこは
「枠の予約はできるが、客室の在庫は別」と範囲を書き直した。

### 押しても何も起きないリンク

- LARU HP のヘッダー「作れるサイト」→ `#works`。**そのidはページに無い**
- `/services` のナビ「会社概要」→ `/#about`、「プロダクト」→ `/#product`。**両方とも無い**
- `/works/[slug]` の「お問い合わせ」→ `/#contact`（実際は `lv-contact`）、
  「概算見積もりを試す」→ `/#estimator`（**その部品はトップで使われていない**）

→ 実在する id に直し、見積もりは `/services#services`（料金の目安）へ。
テストで、ページ内リンクの飛び先が実在するかを機械的に見るようにした。

### 実績の書き方

- `/works/[slug]` が全案件に「企画・設計・開発・運用まで、1名でフルスタック開発」を
  無条件で表示していた。**FLASTAL は企画を担当していないクライアント案件**。
  → 担当範囲を案件のデータ（`structure`）として持ち、案件ごとに出す。
- 同ページの「**モバイルアプリ**の受託開発を一気通貫で」。
  works-data.ts 自身が「iOSアプリはまだ出していない」と書いている。→ 外した。
- 構造化データの `sameAs` に `www.flastal.com` が入っていた。
  `sameAs` は「これも同じ主体である」という宣言なので、**クライアントのサービスを
  自社だと検索側へ伝えていた**。→ 自社運用のものだけに。
- エージェンシーの「クライアント数無制限」→ 実装は999件。「999件まで」に。

### その他の言い換え

- `/laruHP/demo` の「初月無料 · 最低6ヶ月契約 · **いつでも解約可**」→
  6ヶ月の拘束と同じ行にあり、前提が落ちていた。「7ヶ月目から月単位で」に。
- 同ページの「AIが作るサイトのイメージをプレビュー」→ 中身は静的な見本だった。
- ¥999と「チャットボット24時間対応」が同じ画面に並んでいた（¥999にBotは付かない）。
- 業種ページの「フォームに写真を添付できるようにしておくと」→ 添付は未実装。
  折り返しメールで受ける案内に。
