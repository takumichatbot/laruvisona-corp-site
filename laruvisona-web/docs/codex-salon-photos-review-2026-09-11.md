## P2: 非表示の別ページのヒーローが、初期ページの画像を遅延させる

対象: `lib/html-export.ts:1734`。

`heroTakesPriority` を全ページ結合後のHTMLから求めているため、初期非表示のページに `fetchpriority="high"` のヒーローがあると、初期表示ページの画像にも優先指定を付けなくなる。

実際の `exportToHTML` で再現:

1. 1ページ目の先頭にteamブロック（`photo: '/first-visible.jpg'`）。
2. 2ページ目に写真付きheroブロック（`bgImage: '/other-hero.jpg'`）。
3. `heroLayout: 'split'` で両ページを書き出す。

結果:

```html
<!-- 最初に表示するページ -->
<img loading="lazy" decoding="async" src="/first-visible.jpg" ...>
<!-- 初期非表示の2ページ目 -->
<img ... src="/other-hero.jpg" ... loading="eager" fetchpriority="high" ...>
```

前の実装では1ページ目の当該画像に優先指定が付く。今回の修正により非表示ページの画像の有無が表示中ページの判断へ混入した。

他ページの優先指定が表示対象ページの判定へ影響しないよう、ページ境界を保って処理する。結い庵のヒーローだけを優先し下部スタッフを遅延する今回の修正は維持する。2ページの上記ケースと、単一ページの既存ケースを回帰に含める。
