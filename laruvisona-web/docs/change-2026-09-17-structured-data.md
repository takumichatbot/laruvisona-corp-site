# 指名検索で、会社を言い当ててもらう（2026-09-17）

## なぜここに手を入れたか

Search Console で測ると、laruvisona.jp の流入はほぼ**指名検索**だった
（3ヶ月で55クリックのうち、クエリとして見えている非指名は1クリック）。

つまり、いま実際に効く構造化データは「順位を上げるもの」ではなく、
**「この名前は何者か」をGoogleに正確に伝えるもの**である。

ところがその会社の定義が、**2か所にあって食い違っていた**。

```
app/layout.tsx      住所なし／説明は「AIとモダンWeb技術を駆使するテクノロジーパートナー」
                    sameAs は larubot.tokyo だけ
app/local/page.tsx  住所あり／説明なし／ロゴなし／sameAs なし
```

検索側から見ると、同じ会社について違うことを言っているサイトになる。

## 直したこと

### 1. 会社の定義を1か所にした（`lib/organization-ld.ts`）

足りていなかった項目を入れた。

| 項目 | 値 |
|---|---|
| legalName | 株式会社LaruVisona |
| foundingDate | 2026-04-06 |
| email | info@laruvisona.jp |
| address | 東京都板橋区南常盤台1丁目11-6-101号室（174-0072） |
| sameAs | larubot.tokyo / **laruhp.com** / **www.flastal.com** |
| description | 自社サービスを企画・開発・運用しながら、受託開発も請ける会社 |

**sameAs に laruhp.com と flastal.com を足したのが大きい。**
これまでGoogleは、laruhp.com がこの会社のものだと知る手がかりを
持っていなかった。2つのサイトを別々の他人として見ていた可能性がある。

`layout.tsx` と `/local` は、この1つの定義を使う。検査で、自前で
`'@type': 'Organization'` を書いていないことも見ている。

### 2. サイト自体も名乗るようにした（WebSite）

`publisher` で会社と結び、サイトと会社が同じものだと示す。

### 3. 受託の料金を、構造化データにも出した

`/services` に `Service` + `OfferCatalog` を追加。6つのサービスと金額が
検索側から読める。

**金額は画面の `SERVICES` 定数から取り出している。** 別に書き写すと、
料金表を直したときに構造化データだけ古い額が残る。今日、画面と Stripe の
額が9円ずれていたのを見つけたばかりなので、同じ穴は開けない。

- 「¥150,000〜」→ `price: 150000` + `minPrice`（確定額でなく下限であることを示す）
- 「要相談」のように金額が読めないものには、価格を書かない

### 4. パンくずを足した

`/works`、`/works/[slug]`、`/services` に `BreadcrumbList`。
検索結果でURLの代わりに階層が出る。

### 5. トップの説明文から LARUSEO を外した

```
以前: LARU HP・LARUbot・LARUSEO・FLASTALの開発に取り組む…
今:   自社サービスLARU HP・LARUbotを企画から運用まで自社で行う会社です。
      その経験で、Web制作・AI・業務システム・サービス開発の受託も請けています。東京都板橋区。
```

LARUSEO は LARUbot の機能のひとつで、独立した製品ではない。
並べて書くと、実体より製品数が多く見える。あわせて canonical の
末尾スラッシュも sitemap と揃えた。

## 再発防止

- 会社の定義が1か所（layout と /local が自前で書いていない）
- 指名検索で言い当てられるだけの項目がそろっている
- 対応地域を、画面と構造化データで同じ配列から取っている
- **料金を書き写していない**（`serviceOffersLd(SERVICES)` に料金表そのものを渡す）
- 金額が読めないものに価格を書かない
- 参考価格であることが構造化データでも分かる
- 階層のあるページにパンくずがある
- トップの説明文に LARUSEO が入っていない
