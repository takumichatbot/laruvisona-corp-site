# 制作スタジオ：Claude の独立検証への対応

Claude の検証対象は `26da464`。今回は、その後のスマホ編集・取り消し・案の比較を含む `040cc5e` を土台に確認した。

## 指摘への対応

1. **スマホ編集のはみ出し**：`eeaf3ff` で導入済みの、完成像と編集欄を分ける構成を再確認。320 / 390 / 430 / 1440px で画面外への横はみ出しなし。設定欄を開いた状態も検査。
2. **架空の事実が入る問題**：新規スタジオのテンプレートを `starterTemplate()` で内容ごとに整える。架空の体験談・人物は取り込まない。実績数、特徴の断定、料金、営業時間、配送条件、FAQ の回答は入力待ちへ。サービス名などの候補は公開用HTMLの本文にも「【例】」を付ける。写真の alt を直しても候補が残れば公開前チェックは赤。利用者が入力した実績・数値は一括除去しない。工事業で購入目的を選んだ場合も、CTAと商品欄の見出しを一致させた。
3. **開始画面の完成像が遠い**：スマホは画面下に写真・入力した屋号・完成像を開くボタンを固定。開くと同じ公開HTMLによるプレビュー。ページには帯のぶんの下余白を取り、入力欄から離れずに開閉できる。
4. **入力ごとに履歴が増える問題**：既存 iframe の `srcDoc` を再ナビゲーションするのをやめ、新しい iframe の初期文書として置き換える。`sandbox="allow-scripts"` のままで `allow-same-origin` は追加しない。選択位置とスクロールの復元は、送信元を確認した既存の postMessage 経路を使う。
   - 制作段階は `?step=intake|mood|edit` に反映。入力・業種変更では履歴を増やさず、段階を進めたときだけ追加。
   - ブラウザの戻る・進むで段階を移動しても編集内容を保持。見せ方の段階でも、アカウントを照合する既存の端末控えに入力と段階を保存。
   - 初回保存成功後は、履歴を増やさずURLに `siteId` を入れる。再読み込みは所有者の保存APIから同じサイトを開く。URLを更新した瞬間には再取得して編集中の内容を上書きしない。
5. **節名**：`eeaf3ff` で導入済みの日本語名を再確認。「商品・サービス」「3つの特徴」などで表示。

## 関連して修正したもの

空のギャラリーで最初の写真を追加するとき、一覧全体を包む `label` によってボタンのアクセシブルな名前が周囲の文言と混ざっていた。複数入力の組は `fieldset` / `legend` にし、個々の入力・ボタンの名前を維持した。既存の写真編集検証が、空の状態から追加・アップロードする経路を通す。

## 範囲と限界

- テンプレートの整理は**今回の新規スタジオで作り始める内容**に限る。既存の保存済みサイト・過去の下書き・会社トップ・結い庵の作品は書き換えない。
- 公開前の赤い確認項目は現行どおり警告で、公開APIに新たな一律拒否は追加していない。候補・入力待ちが残った場合も、それと分かる本文になる。あらゆる利用者入力の事実性を自動判定する機能ではない。
- `exportToHTML` と公開APIのロジック、EXPORT_VERSION は変更していない。
- 本番の実ログイン、通知送信、実機のソフトキーボード、本番性能の検証ではない。push・デプロイ・本番DB操作・素材生成なし。
