# 「自動でやります」と書いた部分を、本当に自動にした（第2弾）

2026-09-17

第1弾（`change-2026-09-17-public-claims.md`）では、文章と実装の食い違いのうち
「売っているのに使えない」「金額と法定表記」「できるのにできないと書いていた」を直した。

第2弾は、**PARTIAL（条件付きでしか成り立っていなかったもの）を実装で埋める**。

## 1. 検索結果の説明文が、空のまま公開できていた

`lib/laruhp-facts.ts` は「SEOの自動設定（メタタグ・構造化データ）」と書き、
LPは「検索結果の説明文を用意」と書いている。実際は `effectiveSeo.description || ''` で、
自分で書かない限り `<meta name="description" content="">` の空タグのまま公開されていた。
公開前の確認でも説明文は `better`（できれば）扱いなので、空のまま出ていく経路があった。

→ `lib/auto-description.ts`。本文（見出し下の文・段落）から110文字までを作る。
文の途中では切らず、句点で切れないときだけ「…」を付ける。
**自分で書いた説明文があれば必ずそちらを使う**。これは最後の砦。

## 2. 「業種別の構造化データ」が5業種しかなかった

15業種を売りながら、`lib/html-export.ts` に直書きされた分岐は
restaurant / beauty / clinic / fitness / hotel の5つだけ。残り10業種は
汎用の `LocalBusiness` に落ちていた。

→ `lib/industry-schema.ts` に15業種ぶんの表を置き、業種一覧と本数が一致することを
テストで固定した（歯科→Dentist、士業→LegalService、不動産→RealEstateAgent、
税理士→AccountingService、ウェディング→EventVenue…）。

ついでに、構造化データが常に `"url": ""` `"telephone": ""` を出していたのをやめた。
空文字は「無い」ではなく「空がその値」と読まれる。

`EXPORT_VERSION` を 18 → 19。**すでに公開されているサイトのHTMLは、
次の公開時か再生成（`/api/admin/republish-all`）まで古いまま。**

## 3. LARUbotの用意が、黙って飛ばされていた

```ts
if (!process.env.LARU_HP_API_SECRET) return;   // ← これ
```

鍵が無い環境では、bot付きプランを契約してもボットの登録処理が何も起きず、
エラーも記録も残らなかった。**課金は通っているのにボットだけ付かない**状態が
誰にも見えないまま成立する。

→ 例外を投げるように変更。呼び出し元3か所（webhook・checkout・upgrade）は
すでに try/catch していて決済自体は止まらないので、挙動は変わらず、
ログには必ず残るようになった。

## 4. 制作スタジオから届かなかった機能を、届くようにした

LPは全編で「制作スタジオ」を売っているのに、次の2つは旧エディタ
（`/laruHP/builder`）にしか無かった。買った人がLPどおりスタジオを開くと見つからない。

- **AIによる画像の生成** → `components/studio/ImageField.tsx` に「AIで写真を作る」を追加。
  作った画像はアップロードし直してURLで持つ（サイトのデータにbase64を入れない）。
- **Google Analytics 連携** → スタジオの「検索・連絡」に測定IDの欄を追加。
