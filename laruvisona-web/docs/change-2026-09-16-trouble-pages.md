# 困りごと別の入口ページ（2026-09-16）

ブランチ: `company-customers-2026-09-16`（続き）

## なぜ

問い合わせが月0〜2件。料金表を直しても、それは「来た人が見るもの」で、
来る人の数は変わらない。知らない人から連絡が来る経路が1本も無い。

「受託開発 東京」で5ヶ月目の会社が勝つことはない。
一方で、困っている人が実際に打つ言葉なら勝てる。検索した時点で
相手には払う理由があり、しかも競合が広告を出していない。

## 作ったもの

`/trouble`（一覧）と `/trouble/[slug]`（3本）。

| slug | 狙う状態 | 繋がるサービス |
| --- | --- | --- |
| `contact-form-not-arriving` | 問い合わせフォームのメールが届かない | 02 修理 ¥30,000〜 |
| `in-house-ai-tool-risk` | 社内で作ったAIツールが危なくないか | 01 安全点検 ¥150,000〜 |
| `vendor-unreachable` | 制作会社と連絡が取れない | 02 修理／引き継ぎ ¥50,000〜 |

各ページの構成は同じ。

1. こんな状態ではありませんか（症状）
2. 自分で確認できること（順番に意味がある手順）
3. よくある原因
4. それでも直らないとき（価格つき・相談導線）
5. よくある質問（FAQPage の構造化データつき）
6. ほかの困りごとへの内部リンク

## 中身の方針

**本当に役に立つ手順を書く。** 自分で直せる人は直してくれていい、という作りにした。
読んだ人が解決して帰るなら、それでいい。薄い記事で順位だけ取ると、
一度読まれて二度と戻ってこない。

手順は実際に切り分けに使える粒度で書いた。迷惑メールフォルダ、SPFレコードの確認、
開発者ツールでのAPIキー探し、WHOISでのドメイン満了日の確認など。
「ドメインが失効すると取り返せない」のように、緊急度の判断材料も入れてある。

## 追補（同日）: 4本追加して7本に

| slug | 狙う状態 | 繋がるサービス |
| --- | --- | --- |
| `excel-case-management-limit` | エクセルでの案件管理が限界 | 04 仕組みづくり ¥500,000〜 |
| `site-slow` | ホームページの表示が遅い | 02 修理 ¥50,000〜 |
| `accept-card-payment` | サイトでカード決済を受けたい | 05 サービス開発 |
| `ssl-warning` | 「保護されていない通信」と出る | 02 修理 ¥50,000〜 |

`excel-case-management-limit` を入れたのは、日本エンドレスで実際に受けている
仕事とまったく同じ入口だから。単価も一番高い。中身も、実際に運用して分かったこと
（止まった案件を拾う通知、今の列を残す、1画面から始める）で書いている。

`ssl-warning` は緊急度が高い。お客様がサイトを開けない状態なので、
検索した人はその日のうちに誰かに頼む。すぐ金になる種類の入口。

各ページの「ほかの困りごと」は3本までにした。7本並べると選べなくなる。

## 価格の修正

`05 Webサービスの開発` を ¥800,000〜 から **¥1,500,000〜** に上げ、
「まずは1画面・2週間 ¥250,000〜 から」を添えた。

前の ¥800,000 はこちらが根拠なく置いた数字で、FLASTAL級の仕事
（会員登録・集金・返金・匿名配送・管理画面・本番運用）を指す数字としては
下限の下限だった。安い数字を先に見せると、そこが上限に見える。

入口は ¥250,000 で小さく残したまま、本体の相場を正しく見せる形にした。
**この数字も確定ではない。** FLASTALで実際にいくら請求したかが分かれば、
そちらに合わせる。
